# Vercel Blob Storage Integration

The app stores PDF uploads in **Vercel Blob Storage** (`@vercel/blob`). The frontend streams the PDF directly from the browser to Vercel's global CDN using client upload tokens generated by the backend, completely bypassing serverless request body limits (supporting PDFs up to 50MB).

## Flow

1. User selects a PDF in Post Management.
2. The frontend calls `@vercel/blob/client`'s `upload()` function.
3. Vercel Blob client requests an upload token via `POST /api/admin/pdfs/upload-url/request` (handled by `handleUpload` in `backend/services/blobService.js`).
4. The PDF uploads directly from the user's browser to Vercel Blob Storage.
5. The permanent public CDN URL is returned (`https://...public.blob.vercel-storage.com/...`).
6. The frontend saves the record in PostgreSQL via `POST /api/admin/pdfs/upload`.

## Code Paths

- **Backend Vercel Blob Handler & Deletion:** `backend/services/blobService.js`
- **Backend Admin PDF Endpoints:** `backend/services/pdfService.js` & `backend/controllers/pdfController.js`
- **Frontend Direct Upload Client:** `frontend/src/services/api.ts` (`apiService.uploadPdf`)
- **Post Management UI:** `frontend/src/pages/PostManagement/PostManagement.tsx`

## Environment Variables

- `BLOB_READ_WRITE_TOKEN`: Automatically generated and injected by Vercel when connecting the Blob store to your project.
